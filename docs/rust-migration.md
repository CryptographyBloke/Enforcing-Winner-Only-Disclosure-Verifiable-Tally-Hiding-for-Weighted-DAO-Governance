# Rust migration status

Branch: `refactor/rust-native-distributed`. The Rust workspace lives in `native/`; the JavaScript implementation remains in `protocol/` as the current full-ballot reference.

## Workspace

| Crate | Current responsibility |
|---|---|
| `cgy-crypto` | Canonical BabyJub/Base8 point validation, serialization, and group arithmetic. |
| `cgy-protocol` | Existing CGY gate proofs, arithmetic DAG verifier, one-share trustee worker, and canonical public contribution encoding. |
| `cgy-network` | Ed25519 slot authentication, ordered board state, TCP service, fsynced event log, proof-checked recovery, and replay. |
| `cgy-ballot` | Circom WASM witness evaluation, original SnarkJS `.zkey` loading, Rust Groth16 proving and verification, SnarkJS JSON proof/VK decoding, and validation of all 37 public ballot signals. |
| `cgy-chain` | Read-only Ethereum JSON-RPC calls for chain ID, receipts, and logs. The API has no transaction submission method. |
| `cgy-evidence` | SHA-256 artifact manifests and a public-export path filter. |

The binaries are `cgy-native` (compatibility entry point), `trustee`, `coordinator`, `board`, `verifier`, and `runner`. A trustee loads one share and one Ed25519 seed from its own private config file. The coordinator passes config paths to child processes and does not open them. Each trustee creates its contribution and signature in its own process. The board validates the signature and the Rust CGY proof before durably sealing the scheduled contributor set. The board is a trusted sequencer.

## Build and current commands

From the repository root in PowerShell:

```powershell
cargo test --workspace --locked --manifest-path native/Cargo.toml
cargo build --workspace --release --locked --manifest-path native/Cargo.toml
```

The binaries are written to `native/target/release/`.

Rust ballot proving uses the existing circuit artifacts and does not need Node.js at runtime:

```powershell
native\target\release\ballot.exe prove --config runs-private\ballot-prove-config.json
native\target\release\ballot.exe verify --bundle runs\rust-ballot\public\ballots.json --vkey path\to\matching\verification_key.json
```

The private JSON config supplies paths to the matching Circom WASM/R1CS, original `.zkey` and verification key, fresh poll ID, vote/weight test inputs, committee public key, and a new public output path. The command refuses to overwrite an existing output. Keep the config and any witness material under `runs-private/`; the public bundle contains proofs, signals, and phase timings. The compiled circuit and proving-key files are large, setup-specific inputs and are not committed. A test-only setup key does not match the fixed verifier contract. Use a key whose verification key matches the deployed Solidity verifier.

```powershell
native\target\release\runner.exe local-gate path\to\gate-request.json
native\target\release\board.exe --config path\to\public-board-config.json
native\target\release\coordinator.exe --plan path\to\public-execution-plan.json
native\target\release\verifier.exe gate path\to\single-gate.json
native\target\release\verifier.exe board --config path\to\public-board-config.json
native\target\release\runner.exe chain-preflight --rpc $env:ARBITRUM_SEPOLIA_RPC_URL
```

`coordinator --plan` consumes an explicit public phase plan and trustee config paths. The board runs separately. The plan must provide each phase's exact trustee set and public context. It is a phase executor, not the current weighted-election DAG builder. `local-gate` is a local reference command; do not use it to claim share isolation.

## Compatibility and current boundary

The Rust CGY verifier retains the existing protocol domain strings, BabyJub/Base8 profile, ciphertext coordinates, proof statements, and gate transcript verifier. A Rust test fixture generated by the JavaScript board code checks byte-for-byte slot encoding and Ed25519 signature agreement. The existing native-vs-JavaScript gate compatibility script remains available.

The Rust TCP board stores a Rust-specific JSONL wrapper around the original public payload bytes. It verifies the same signed slot bytes and CGY proof statements. Conversion to the existing JavaScript board-export schema has not been integrated into the full ballot runner.

The full Rust migration is not complete:

- Rust now handles witness evaluation through the Circom WASM interpreter, Groth16 proving from the original SnarkJS `.zkey`, and Groth16 verification. A fresh Rust-generated n=8 ballot bundle was accepted by the unchanged Solidity verifier. `ballot verify` also accepted the eight frozen SnarkJS fixtures against the original verification key. The public experiment runner, ballot admission, weighted DAG, full distributed protocol, chain-to-board binding, and public replay remain outside this Rust ballot CLI.
- The existing ballot admission path, arithmetic DAG construction, ready-gate scheduler, local-scale runner, and oracle comparison remain JavaScript.
- The Rust chain crate provides read-only JSON-RPC methods, not Solidity ABI decoding, deployment, transaction signing, or full accepted-board reconstruction.
- The Rust board/coordinator/trustee binaries compile and the board has TCP/persistence smoke coverage. A complete n=8 election using only these Rust binaries has not passed yet. No n=64 Rust-native run has been made.
- Rust was built and tested on Windows in this migration. Linux CI execution is configured only after the workflow change; no Linux result is claimed here.

The NETWORK-03 n=8 run is kept separate from Rust-only acceptance. Its five trustees generated live CGY contributions in Rust processes and the public verifier passed, but Node still scheduled the DAG and ran the TCP board. It is evidence for the Rust cryptographic workers, not a pure-Rust end-to-end run. See [`reports/RUST-01.md`](../reports/RUST-01.md) for the exact run ID, verification state, and migration status.

## Public and private artifacts

Keep trustee config files (shares and authentication seeds), ballot witnesses, and oracle inputs outside public output directories. `cgy-evidence::public_artifact_allowed` rejects private/oracle directories, witness/key extensions, and known plaintext-secret filenames. Its path filter is one export check; validate every exported bundle before publication.
